# A README checklist for side projects

A README is the front door of a repository. It should let a stranger understand the project and run it without reading the source first.

## Key practices

- Start with a one-line pitch that explains what the project does and who it is for.
- Show a screenshot, demo link, or short animated example.
- List prerequisites and exact install and run commands.
- Document configuration values and where they come from.
- State the license and how to contribute or report a bug.

## Why it matters

A clear README increases adoption, reduces support questions, and makes the project easier to maintain.
