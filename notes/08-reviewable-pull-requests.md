# Writing pull requests that are easy to review

Review quality depends on how much context a reviewer has to reconstruct. A good pull request makes the change obvious before the reviewer opens the diff.

## Key practices

- Keep the diff focused; split unrelated changes into separate pull requests.
- Explain the problem, the approach, and the risks in the description.
- Link the issue or design document that motivated the change.
- Call out the files or decisions that deserve extra attention.
- Include screenshots or recordings for visible UI changes.

## Why it matters

Reviewers spend less time reconstructing intent and more time finding real problems.
